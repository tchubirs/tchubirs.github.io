# Codex code review

Second-opinion review of the current changes. Scope from $ARGUMENTS: empty or "uncommitted" means `git status --short`, `git diff`, `git diff --cached` plus the full contents of new untracked files; a branch name means `git diff <branch>...HEAD`; a SHA means `git show <sha>`. If the diff is empty, say so and stop. If it is over 50,000 characters, summarize and warn. Call `codex_exec` with mode "exec", requireGit true and the prompt: "Review the following code changes. For each finding, specify: severity (CRITICAL/HIGH/MEDIUM/LOW), file and line, description, and suggested fix. Focus on: bugs, security issues, performance problems, error handling gaps, and readability." followed by the diff. Verdict: BLOCKED (at least one CRITICAL or HIGH), WARNING (only MEDIUM or LOW), APPROVED (none). Present findings by severity with your own agree or disagree. Offer a fix loop (at most 3 rounds) only with the owner's go-ahead. If Codex is missing, not logged in or offline, fall back to your own review.
